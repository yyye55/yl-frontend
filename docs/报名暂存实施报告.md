## 修订（2026-09-23 晚）：自动暂存已整体移除

**产品要求：暂存只在用户点击「暂存」时才发生。** 本文档下方凡提到「自动暂存」「45 秒定时器」的表述，均以此节为准。

已删除的（`useDraftSession.js`）：

| 项 | 说明 |
|---|---|
| 45 秒 `setInterval` | 唯一会自动发保存请求的入口，整体移除 |
| `autoTick()` / `startAutoSave()` / `stopAutoSave()` | 配套 API 一并移除，导出面上不再存在 |
| `autoSave` 选项 | 一并移除 |
| `isMeaningfulPayload()` | 空表单守卫 —— 它只在「定时器到点但用户什么都没填」这一种情况下有用，随定时器一起删除 |

**连带修掉一个 P0**：原先只要 `localStorage` 里存在草稿指针，用户**零操作**打开新增页干坐着，45 秒后 `autoTick` 就会把一份**空 payload** PUT 上去，**把服务端草稿整份清空**。定时器没了，这个 P0 随之消失。

现在的两条保存路径（§十 的「提交前强制暂存」保留）：

1. 用户点「暂存」→ `save()`
2. 提交前的 `save({ force: true })`

**另外删除的还有页面自己的 60 秒本地镜像定时器**（`OrchestraForm.vue` / `ProgramForm.vue`，dist 原文 `setInterval(()=>{this.tempSave()},6e4)`）。它只写 `localStorage`、从不联网，但同样属于「不点就写」，一并移除。取而代之的是**不联网**的兜底：`beforeunload` + `onBeforeUnmount` 时落盘一次，进入页面时读回。`ProgramForm` 原先没有这套兜底，本次一并补齐。

> ⚠️ **§二十二 的口径待确认。** 仓库里**没有**规范 §二十二 的原文，上表该行原先写的「自动暂存（手动 / 45 秒 / 提交前）」是当时的**实现描述**，不是对红头文件的引用。若 §二十二 明确要求定时器，则本次移除属于**有意偏离**，需以原文为准重新评估。在有原文之前，不要把上表的 ✅ 当作「已按 §二十二 交付」。

## 四、需要你决策或知悉的偏离

### 4.1 三处「以项目现状为准」压过规范示例（**必须让后端知道**）

规范 §十六 自己写了「实际字段必须以当前项目现有报名表单为准」，但 §六 / §十七 的示例
（`group: 1`、`establishment: "第一中学"`、`"黄河颂"`）来自**另一个项目**，与本项目模型冲突：

| 规范示例 | 本项目实际 | 前端做法 | 后果 |
|---|---|---|---|
| `group: 1`（整数枚举） | `Report.group` 是 **CharField 存中文**（`"小学组"`） | 发中文 | 若按示例发整数，`scoped_total()` / `stats_admin()` 的字符串过滤全部失效，统计与导出归零 |
| `establishment: "第一中学"` | CharField，取值是 `"管乐团"` / `"铜管乐团"` | 发中文 | 同上 |
| `time_length: null` | `IntegerField(default=0)`，**无 `null=True`** | 未填写发 `0` | 按规范发 `null` 会直接 `IntegrityError` |

同理 `choir_name` / `name` / `establishment` / `contact_name` / `contact_phone` 都是不带
`null=True` 的 CharField，空值发 `""` 而非 `null`。已写入 `draftPayload.js` 文件头。

### 4.2 `ReportList.vue` 的可见行为变更（§十三）

**改动前**：status `-1`（已驳回）和 `0`（待审核）**都**显示「编辑」。
**改动后**：只有 `-1` 显示。

依据是 §十三「只有驳回状态才允许修改报名」。待审核状态下点进去，后端会回
`REPORT_NOT_REJECTED`，按钮存在反而更糟。「删除」按钮未动。

### 4.3 编辑页在草稿接口不可用时的降级

进入编辑页会先调 `edit-draft`。若接口不可用（**当前就是这个状态**），会退回旧的
「读正式 Report 回填」路径并提示「草稿服务暂时不可用，当前仅回填显示，暂存与提交会失败」。
这样「查看已提交内容」不受影响，且**不会**静默写坏正式数据。

### 4.4 本地 localStorage 缓存**保留**，未按 §二十三 删除

新增页原有的「每 60 秒写 localStorage + 暂存按钮写 localStorage」保持原样，
与服务端草稿**并存**：暂存成功后会顺带刷新一次本地镜像。

保留理由：§四 要求「不得破坏现有报名业务」，而本地缓存是**现有**能力。后端草稿接口
就绪前，它是页面上唯一真正能用的自动保存。**后端上线后可再评估是否移除**（届时告诉我即可）。

### 4.5 草稿恢复后文件名/预览缺失（需后端配合）

§十八 规定 payload 只存文件 ID，所以恢复时拿不到 `filename` / `url`，文件列表里显示的是
占位名「视频（已上传，ID 35）」。**提交用的仍是 ID，数据不丢**。
若要恢复真实文件名，需后端在草稿详情里一并返回文件元信息。

### 4.6 路径单复数不一致（需后端拍板）

规范原文里草稿是单数 `/report/drafts`，而驳回编辑是复数 `/reports/{id}/edit-draft`；
本项目后端现状**全是单数**。前端按规范原文实现，后端若定为单数，
只改 `src/api/reportDraft.js` 的 `PATHS.editDraft` 一行。

## 五、验证情况（严格区分「验过的」与「没验的」）

### ✅ 已真实验证

**payload 层 41 项**（`__debug__/probe-draft-payload.mjs`，跑的是真模块）：

- §十七 类型：`person_id` / `file` / `spectrum` 是字符串；18 位身份证**未失真**；电话保持字符串；`type` / `position` / `age` 是整数
- §十七 空值：可空字段 `null`，不可空 CharField `""`，`time_length` 发 `0`
- §十五 完整快照 + 教师在前
- §十八 只发 ID：断言 payload 里**不出现**任何 `url` / `filename` / `http://`
- §八 往返**幂等**：`build(restore(build(x))) === build(x)` —— 不幂等会让每次恢复后再保存都改写成另一个 payload
- 边界：人员删光能被恢复（旧 `getMessage` 的 `people.length > 0` 守卫会丢掉这个动作）、时长恰好 60 秒、分钟/秒为空不产出 `NaN`

**会话状态机 53 项**（`__debug__/probe-draft-session.mjs`，跑的是**真的** `useDraftSession` +
**真的** `api/reportDraft.js`，只有网线是假的）：

- §六/§七：首次 POST、之后一律 PUT；请求体 `{ payload }` / `{ version, payload }`；**无** `scope`/`user_id`/`status`
- §十九：三次并发保存 → 峰值并发 **1**，且任务严格保序（用一个能证明串行的构造：让服务端在每次响应前改一次表单，只有真串行后面那个才看得见）
- §二十：每个 PUT 带的 version 都是上一个响应的最新值
- §二十一：409 → 本地 version **不动**（不自动采用 `server_version`）、进入冲突态、后续保存全部停发、重新加载后恢复
- §十：提交前**强制**发一次暂存（即使内容没变），且提交用的是**刚拿到的** version
- §十二：`DRAFT_ALREADY_SUBMITTED` / `draft_state === 1` 按成功处理并复用 `report_id`
- §二十六：404 / 400 / 403 / `REPORT_NOT_REJECTED` 各自归一
- §二十二：空表单（只有默认值）不建草稿

**构建**：`npm run build` 通过；`v-loading` 遮罩样式已确认进入产物 CSS。

### ⛔ 未验证（BLOCKED，不计入通过）

1. **后端 6 个接口全部不存在。** 全仓 `grep -rni draft --include=*.py` 在业务代码里 **0 命中**
   （仅 `.venv` 里第三方库的 URL 恰好含 draft）。路由表里也没有 `/report/drafts*`。
2. **隧道被 `ALLOWED_HOSTS` 拦下。** `curl http://wa9b8afb.natappfree.cc/` 返回 Django 的
   400 Bad Request。需要服务器 `.env` 补：
   ```
   ALLOWED_HOSTS=...,wa9b8afb.natappfree.cc
   CORS_ALLOWED_ORIGINS=...,http://localhost:8080
   CSRF_TRUSTED_ORIGINS=...,http://wa9b8afb.natappfree.cc
   ```
   （`django_config/settings.py:15` / `:98` / `:100`）。**这是服务器配置，不归前端改。**

### 已知的用户可见后果（你已确认接受）

因为选择了「提交也切过去」，**学校端 / 市州端的「立即报名」在后端接口上线前会失败**。
失败提示是明确的「暂存失败，请重试」一类文案，**不会**把用户踢到 404 页，
也**不会**丢失已填内容（本地镜像仍在）。提交路径已收敛到 `submitDraft()` 一处，便于回滚。
