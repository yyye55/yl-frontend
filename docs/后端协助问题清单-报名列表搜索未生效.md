## 四、这次改动到底改了什么

`apps/api/views.py` 的 `report_queryset`，`keyword` 那一段。

**改之前**：匹配范围**取决于调用方**，同一个搜索框在不同身份页面上搜的范围不一样。

```python
if keyword:
    if current_user or user_ids is not None:
        qs = qs.filter(name__icontains=keyword)              # 市州/高校/中小学：只搜曲目名
    else:
        qs = qs.filter(Q(name__icontains=keyword)
                       | Q(choir_name__icontains=keyword))   # 管理员/组委会：多搜一个乐团名
```

`school_name`（学校名）**在两条分支里都搜不到** —— 这正是前端当初不得不另摆一个
「学校名」输入框的原因，而那个框走的是 `school_name` 独立参数，与 `keyword` 是 **AND**
关系，同一个词填进两个框必然得空表。

**改之后**：三支合一，一个框搜三个字段，与身份无关。

```python
if keyword:
    qs = qs.filter(
        Q(name__icontains=keyword)
        | Q(choir_name__icontains=keyword)
        | Q(school_name__icontains=keyword)
    )
```

`choir_name` / `school_name` 两个**独立参数原样保留**（下面几行没动），
历史请求或外部调用传了仍然生效。

### 1. 前端侧的确认方法（不需要开发环境）

浏览器 F12 → Network → 在搜索框输入关键词并回车 → 找到
`report/list?keyword=...` 这条请求，看两个地方：

- **请求 URL 里有没有 `keyword=你的词`**

- **响应的 `data` 字段**

  - `data: [ ...有内容... ]` 但页面表格是空的 → 前端渲染问题，发回给我。
