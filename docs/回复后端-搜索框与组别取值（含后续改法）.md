## 三、前端已修：三个页面的「组别」下拉传了不存在的值

### 3.1 问题

三个页面的「组别」下拉，选项写的是**拼接串**「管乐团-小学组」「铜管乐团-中学组」这类值。

但「管乐团 / 铜管乐团」和「小学组 / 中学组 / 大学组」在后端是**两个独立列**：

| 列 | 含义 | 取值 |
|---|---|---|
| `Report.establishment`（`models.py:220`） | 乐团类别 | `"管乐团"` / `"铜管乐团"` |
| `Report.group`（`models.py:219`） | 参演组别 | `"小学组"` / `"中学组"` / `"大学组"` |

第十二届的 5 个正式组合（管乐团×{小学,中学,大学} + 铜管乐团×{小学,中学}）
是**这两个维度的乘积**，不是 `group` 列的取值。

而这三个页面对 `group` 走的都是**精确过滤**，`group` 列里又没有「管乐团-小学组」这个字符串 ——
**所以选任何一项都是整页空表。** 这就是「组别下拉一选就空白」的原因。

### 3.2 三条链路（这就是「取错值必然空表」的证据）

| 页面 | 前端调用 | 后端接口 | 后端函数 | 对 group 的处理 |
|---|---|---|---|---|
| `/admin/report` | `adminApi.report.getList` | `GET /api/admin/report/list` | `report_queryset`（`views.py:95`） | `:127` `qs.filter(group=...)` 精确 |
| 组委会展演页 | `committeeApi.online.getList` | `GET /api/committee/online/list` | `views.py:937` → `role_error(2) or live_page` | `:251` `qs.filter(group=...)` 精确 |
| 展演列表页 | `liveApi.getLiveReportList` | `GET /api/live/list` | `live_page`（`views.py:241`） | `:251` `qs.filter(group=...)` 精确 |

### 3.3 处理结果（前端侧已了结，**不需要你们做任何事**）

前端把三个下拉改成真值（`小学组 / 中学组 / 大学组`，与后端取值逐字相同）之后，
**这三个页面在同一天的仓库清理中被整体删除** —— 它们的路由在 `main` 上早已摘除
（`router/index.js` 的「已删除 15 条用不到的路由」清单里就列着 `/admin/report`、
`/online/list`、`/committee/online`），菜单里也无入口，属于**打不开的死代码**。

| 页面 | 归属 | 现状 |
|---|---|---|
| `src/views/admin/report.vue` | 管理员端报名审核 | **已删除**（报名审核由组委会菜单承担） |
| `src/views/committee/online.vue` | 西部学校音乐周展演（**另一场活动**） | **已删除** |
| `src/views/online/list.vue` | 同上 | **已删除** |

**⇒ 这个 bug 随页面一起消失。**

本节保留的价值只剩一条：**它把 `group` 的数据模型定下来了** ——
`group` 是「参演组别」（小学组 / 中学组 / 大学组），
`establishment` 是「乐团类别」（管乐团 / 铜管乐团）**独立一列**，
系统中**不存在**「管乐团-小学组」这种拼接值。第四节 4.1 正是从这条结论来的。

## 四、后续改法（本次请评估，不急）

### 4.1 请求：给报名列表接口增加 `establishment` 过滤参数

> ⚠️ 这一条要改后端，所以**先问你们，不默认做**。你们评估后说行不行都可以。

**背景（这不是我们想加功能，是菜单里已经挂着一个待办）**：

前端组委会菜单 `src/config/menus.js` 里有一行被注释掉的入口，原话是：

```js
// 【第十二届隐藏】铜管乐团审核入口待后端确认后添加
// { index: '/committee/elementary4', text: '铜管乐团审核', label: '铜管乐团审核', icon: 'el-icon-s-data' },
```

红头文件里「铜管乐团分为小学组、中学组」，组委会需要**单独审铜管乐团**的报名。
但现在的组委会审核页 `CommitteeReportList.vue` **只能按 `group` 筛**
（它的 props 只有 `group / groupLabel / pageTitle / columns`，请求里也只带 `keyword / group / status`），
所以「只看铜管乐团」这个页面**做不出来** —— 卡点在后端没有第二个过滤参数。

**卡在哪**：`report_queryset`（`views.py:95-131`）只读 `keyword / status / group / choir_name / school_name`，
没有 `establishment`；`establishment` 列（`models.py:220`）存在，只是没人按它筛过。

**建议改法（纯增量，不带参数时行为逐字不变）**：

`apps/api/views.py` —— `report_queryset` 里，在 `group` 那段（`:126-127`）旁边加一段：

```python
    if request.GET.get("establishment") not in (None, ""):
        qs = qs.filter(establishment=request.GET.get("establishment"))
```

（`live_page`（`:241`）**不用改** —— 它服务的两个展演页本轮已随仓库清理删除。）

前端会按「参数为空就不传」的方式接，因此**不传 `establishment` 的请求与改动前完全等价**，
不会影响任何已有调用方。

**为什么不建议反过来「把两个维度拼成一列存」**：
`group` 这个列现在被四处依赖 ——
`registration_form.py:260`（校验白名单 `("小学组","中学组","大学组")`）、
`views.py:512`（统计三档）、
`export_services.py:97`（导出映射 `{"小学组":1,"中学组":2,"大学组":3}`）、
`migrations/0009` 的字段注释。
动这一列要连带改四处 + 洗历史数据；而加一个过滤参数是零风险的。

**如果你们评估后不想加**：也回我们一声就行。我们会**继续保持那行菜单注释为注释状态**
（铜管乐团审核入口不上线），并在注释里补一句「阻塞原因：后端 `report_queryset` 无
`establishment` 参数」—— **不再提这个需求。**
