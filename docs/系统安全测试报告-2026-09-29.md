## 零、结论速览

### 0.1 一句话结论

系统在**鉴权收口**与**数据隔离**这两条主线上做得比同规模项目扎实（见第八节，107 条接口有 100 条签了
统一鉴权，SQL 注入、路径穿越、反序列化、模板注入等常见面均已排查干净，未发现真实云厂商凭证入库）。
问题集中在三处：

1. **逐接口手写鉴权，漏一条就是一条** —— `role_error` / `_committee_type_scope` / `export_report_scope` /
   `subordinate_school_ids` 四个 helper 靠人工记得调用，`/api/scan/list` 与 `/api/file/list` 就是漏掉的两条；
2. **写入侧字段白名单不完整** —— 报名创建漏了 `status`、用户修改漏了 `type`，两处都属于「同一文件里
   另一条路径已经拦了、这一条忘了拦」；
3. **导出层完全没有对用户输入做转义** —— 这一条的后果最重：它把 PDF 导出变成了一个可对内外网发起
   请求、并可读取服务端本地文件的**原语**（S-03）。

其中 **S-01（组委会提权为管理员）**、**S-02（匿名批量泄露观众个人信息）**、**S-03（PDF 导出 SSRF）**
三条建议列为第一优先级，应在下一次对外发布前处理。

## 一、测试方法与可信度说明

### 1.1 为什么这份结论不是「读代码读出来的」

本机原本跑不起后端（无 `.venv`、无 Postgres、`requirements.txt` 钉的 Django 3.2 与全局 5.2 不匹配）。
本次先解决了运行环境，使得**报告里每一条都能给出一条可执行命令，并已当场跑出结果**：

- 依赖：按 `requirements.txt` 逐条安装**同一批版本**（`Django==3.2.24`、`django-ninja==0.22.2`、
  `pydantic==1.10.15`、`reportlab==4.2.2`、`openpyxl==3.1.5`、`bcrypt==4.1.2`）；
- 数据库：**唯一**的替代项，用 SQLite 顶替 Postgres/GaussDB。`core` 全部 20 个迁移
  （含 `0009` 的触发器 DDL）在 SQLite 上完整应用通过；
- 请求路径：走**真实的 `django_config.urls` → 真实中间件 → 真实 `apps/api/views.py`**，
  不是把这几个函数单独拉出来调用；
- 数据：全部为本进程当场创建的探针账号与记录，**未连接任何生产库，未对生产发起任何请求**。

### 1.2 证据等级的读法

- **已跑红**：报告内附实际输出或命令。可信度约等于「在生产上必然复现」，前提是生产配置与代码一致
  （个别条目依赖 `.env`，已单独标注）。
- **代码已确认**：逐行核对无误但未运行时复现，通常是「影响面需要真实浏览器 / 真实 OSS / 真实网络」的那几条。
- 凡属推测，报告内一律写成「疑似」并说明缺什么证据，**不与其他条目混在一起计数**。

### 1.3 复现环境

搭建步骤见附录 A。整个探针工程是一次性的，**未写入任何仓库**（位于系统临时目录）。

### 1.4 本次测试没有覆盖的

- 生产环境的实际配置（`.env` 内容、Nginx 规则、防火墙策略）；
- 真实 OSS / CDN 的读写权限与 Content-Type 处理行为；
- 依赖库的具体 CVE 编号 —— 需用 `pip-audit` / `npm audit` 跑，本报告不凭记忆列编号。

## 二、严重问题（🔴）

### S-01　组委会可把任意学校账号提权为管理员，并用硬编码默认口令登录

**位置**：`apps/api/views.py:671`（`user_update_admin`）

```python
user = User.all_objects.filter(Q(pk=data.get("id")) & _committee_type_scope(request)).first()
for k in ("username", "nickname", "description", "tel", "leader", "type"):
    if k in data: setattr(user, k, data[k])          # ← type 直接来自请求体
...
if "password" in data: user.set_password(RESET_PASSWORD_DEFAULT)   # 592 行常量
```

`_committee_type_scope` 只约束**目标在改动前是什么类型**（必须是 0/1/5），完全不约束**改成什么类型**。
于是「目标原本是学校账号」这一关一过，`type` 可以写成 `3`（管理员）。
同一请求里带一个 `password` 键，口令还会被重置为硬编码常量 `scylb@2026`（`views.py:592`），
攻击者无需读库就知道新口令。

**完整利用链三步，全部已在本机真实代码上跑通**：

```
[RED] F7   组委会 PUT /api/committee/user/ 把学校账号(0)升为管理员(3)
            HTTP 200  code=0  type: 0 -> 3
[RED] F7b  被提权账号可用硬编码默认口令登录，且已是 type=3
            code=0  user.type=3  token=<REDACTED>
[RED] F7c  用提权出来的 token 可访问 /api/admin/user/list（全平台账号管理）
            HTTP 200  {"data": [{"id": 2, "username": "probe_committee", ...
```

**这是漏写而非设计，有两处对照**：

- 同一函数族的**创建**路径 `user_create_admin`（`views.py:689`）硬编码 `values["type"] = 0`，
  即组委会建号只能建学校账号；
- 仓库现有测试 `tests/test_auth_permissions.py:354`（`test_committee_update_cannot_modify_admin_account`）
  只断言「组委会改不了**已经是**管理员的账号」，从未断言「组委会不能把学校**改成**管理员」。

修法见第七节 7.1。**这一条建议与 H-07（默认口令）一并处理** —— 单修提权，攻击者仍可把目标
重置为已知口令后登录，只是拿不到管理员权限。

### S-02　匿名批量泄露观演预约个人信息

**位置**：`apps/api/views.py:1342`（`GET /api/ticket/list`，**无 `auth=`**）

```python
@api.get("/ticket/list")                      # ← 无鉴权
def ticket_list(request):
    qs = Ticket.objects.filter(type_name=request.GET.get("type_name"))
    ...
    d = model_dict(ticket)
    d["subscribe"] = [model_dict(x) for x in
                      TicketSubscribe.objects.filter(ticket_id=ticket.id)]
```

`model_dict` 返回整行，`TicketSubscribe` 含 `name / card（身份证后6位）/ phone / ip / code`。
`type_name` 就是公开预约页上展示的场次名，无需猜测。

**实测输出**：

```
[RED] F3  未登录即可 GET /api/ticket/list 拿到预约人 姓名+身份证后6位+手机号+预约码
          HTTP 200  返回 2 位预约人；首条：
          [{"name": "张三", "card": "510199", "phone": "13800000001",
            "code": "260115133000123456789"}, ...]
```

`openapi.json` 中 100 条路径有 7 条未声明任何鉴权，其中 `/api/ticket/*` 占 5 条
（`list` / `message/{code}` / `my` / `make`），全部已在 0.1 节之外单列于 H-04、H-05。

**旁证**：`yilinbei hou/.env.example:8-9` 与 `DEPLOYMENT.md:80` 的注释都把
「`/api/ticket/*` 是公开的、会返回个人信息」写进了「不能放开 CORS」的理由，
说明这是一处**已知的取舍**。本次测试不质疑预约接口本身要对公众开放的判断，
但要求：**列表接口不应逐条回吐预约人信息**（详见第七节 7.3）。

### S-03　PDF 导出未转义用户输入 → 盲 SSRF + 任意本地文件读取

**位置**：`apps/api/registration_form.py:283`

```python
def cell(text, style="body"):
    return Paragraph(text, styles[style]) if str(text) else ""     # ← 无任何转义
```

同一仓库的 `apps/api/person_export.py:192-195` 是**正确写法**：
`Paragraph(escape(str(text)).replace("\n", "<br/>"), style)`。
同一类数据、同一个库，一份转义一份不转义。

reportlab 的 `Paragraph` 接受类 HTML 的标记。测试证实了两档后果：

**第一档：确定性拒绝服务（已跑红）**
用户把曲目名写成 `<b`（未闭合标签），`/api/export/report` 直接 500：

```
[RED] M3a  PDF 导出未转义用户输入 → 抛异常
           ValueError: paraparser: syntax error: parse ended with 1 unclosed tags
```

由于该接口只导出 `status=1` 的报名，而学校账号可以自己把 `status` 写成 1（见 S-04），
**一个低权限账号可以持续让组委会与管理员的整批导出失败**。

**第二档：盲 SSRF + 服务端本地文件读取原语（已跑红，后果更重）**

把曲目名写成 `<img src='…'/>`，导出时 reportlab 会去**主动请求**该地址：

```
[M3b] GET /api/export/report → HTTP 200  77035 字节  CT=application/pdf
      探针 HTTP 服务器收到：['/ssrf']         ← 服务端确实发起了这次请求
```

指向服务端本地路径时，reportlab 同样会去打开它（实测把路径换成本机一个真实 PNG，
导出正常返回，说明该文件被成功读取并解码）：

```
[M3c] 报名名称里塞服务端本地路径 ……\yl-probe-local.png
      GET /api/export/report → HTTP 200  77020 字节
```

**实际危害的准确边界**（避免夸大）：

- **可利用**：服务端按攻击者给定的 URL 发起请求（可用来探测内网服务、访问只有服务器能访问的地址、
  配合云元数据端点等）；服务端按攻击者给定的路径读取本地文件。
- **不可直接回显**：非图片格式的文件（`.env`、`settings.py`）会被静默跳过，内容不会出现在 PDF 里。
  所以这一条**不是**「任意文件读回显」，而是「任意的服务端文件读取 / 出网请求原语」。
  这一措辞差别很重要，请照此理解。

**触发者**：任意学校账号（经 S-04 把自己的报名置为 `status=1` 即可进入自己的导出）；
**不需要**该账号具备管理员权限 —— 但它同时也能污染管理员的导出。

### S-04　报名创建可注入 `status` —— 学校自审批

**位置**：`apps/api/views.py:159-171`（`create_report`）

```python
values = {f.name for f in Report._meta.fields}
values -= {"id", "created_at", "updated_at", "deleted_at", "user_id"}
payload = {k: v for k, v in data.items() if k in values}
for key in ("read", "minute", "second", "fileList", "person"):
    payload.pop(key, None)
...
report = Report.objects.create(user_id=user.id, **payload)
```

剔除集合与弹出集合里都**没有 `status`**，`Report._meta.fields` 里有 `status`，于是它被原样写入。

**实测输出**（用一个干净的新账号，避开配额限制）：

```
HTTP 200 code= 0 msg= 创建成功
返回体里的 status = 1  remark = 客户端自填的审核备注
库里落地的行 = {'status': 1, 'remark': '客户端自填的审核备注', 'name': '探针自审'}
```

**这是漏写而非设计，有两处对照**：

- 同一文件的 `update_report`（`views.py:204`）显式把 `status` 排除出可写集合，
  并在 214 行强制 `report.status = 0`；
- 草稿提交路径也干净（`report_drafts.py:51-58` 的 `REPORT_FIELDS` 不含 `status`）。

即：**只有「直传创建」这一条路漏了**，其余两条都拦了。受影响路由为
`POST /api/{school,primary,province}/report/create`（三个渠道共用 `create_report`）。

**注意本条的连带效果**：它把 S-03 的毒化报名送进了「只导出已通过报名」的导出结果里，
是 S-03 在低权限下的可用前提。两条应一并修复。

## 四、中（🟡）

### M-01　token 为滑动过期，持续使用的 token 永不失效

**位置**：`apps/core/models.py:203` 判据是 `last_used_at < now - TOKEN_TTL_HOURS`，
而 206-207 行**每次认证都把 `last_used_at` 刷成 `now`**。

也就是说 `TOKEN_TTL_HOURS = 4` 是**空闲超时**，不是**绝对寿命**。

**实测输出**：

```
[M1] TOKEN_TTL_HOURS = 4（判据是 last_used_at 距今超过 4 小时才失效）
     对照：闲置 5 小时后调用 → HTTP 401，token 行已被删除 = True
     把 last_used_at 每次置为「距上次使用 4 小时 50 分」，再调一次接口，重复 8 轮：
     8 轮里全部成功 8 次；累计模拟经过 30.7 小时（TTL 只有 4 小时）
     → 持续在用的 token 永不失效 = True
```

「闲置 4 小时就失效」本身是对的（对照组证明），问题在于**攻击者只要保持低频调用即可无限续期**。
与 H-02 叠加：账号被盗后即便改密，token 也不会失效。

### M-02　列表分页 `limit` 无上限，叠加序列化 N+1

`apps/core/services.py:89-101`：`limit = max(1, int(request.GET.get("limit", 10)))` —— 只有下限没有上限。
`/api/scan/list` 的序列化函数**每行触发一次 `ScanFiles` 查询**，即 `?limit=1000000` 是一次请求打满整表。
实测 `?limit=99999999` 返回 HTTP 200（本机数据量小，不作规模断言，但边界确认无上限）。

### M-03　登录时 token 无限累积

`views.py:294` 每次登录都 `PersonalAccessToken.issue(user)`，不失效旧条；
清理中间件只清「空闲 > 4h」的。同一账号的历史 token 会持续堆积，其中仍活跃的那些不会被动过（见 M-01）。

### M-04　前端 token 存 `localStorage`

`yl-frontend/src/utils/auth.js:22`，键 `token`，值为 `"Bearer " + 明文`。
**当前无可达的 XSS 路径**（全仓 `v-html` / `innerHTML` / `eval` / `new Function` 零命中，
唯一 `dangerouslyUseHTMLString: true` 是登录页的静态文案），所以这不是一个「已可被利用」的问题。
列出它的原因是：它把**未来任何一次 XSS 的后果**放大为「长期有效的账号完全接管」——
因为 token 不能被 httpOnly 保护，且按 M-01 不会自己过期。属架构取舍，建议记入技术债而非立即改造。

### M-05　未强制 HTTPS、无 HSTS

`settings.py:96-97`：`SECURE_SSL_REDIRECT` 默认 `False`、`SECURE_HSTS_SECONDS` 默认 `0`（实测确认）；
`SECURE_PROXY_SSL_HEADER` 未设置。`deploy/deploy.sh` 的 Nginx 监听 80。
`deploy.sh:108-110` 虽跑 `manage.py check --deploy`，但脚本注释自陈这些告警**不影响退出码**，
即不构成阻断。登录口令与 Bearer token 会走明文 HTTP。
（线上响应头本次未验证 —— 未对生产发起请求。）

### M-06　`/api/qiniu/token` 发放整桶上传凭证

`views.py:343-352`：`Auth(...).upload_token(settings.QINIU_BUCKET)` **未传 `key`**，
按七牛 SDK 语义即 scope = 整个 bucket 的凭证，可在该 bucket 内写任意 key（含覆盖既有对象）。
只要求登录，不校验角色。前端已弃用该接口（`qiniuApi` 为死代码），**但后端路由仍暴露**。
对照：阿里云 OSS 那套做对了（`views.py:1500-1505` 把 STS 策略收敛到 `{biz}/{日期}/` 前缀，key 由服务端 `uuid4` 生成）。
**是否生效取决于 `.env` 是否仍配置七牛**（本机未配置，故只能标为代码已确认）。

### M-07　上传登记与直传路径的类型 / 扩展名校验缺口

- `POST /api/file/create`（`views.py:355`）不校验 URL 协议、域名、大小、类型，也不校验文件是否真存在于 OSS；
  配合 H-03 可把任意 URL 登记成「自己的文件」并挂到报名表上；
- `POST /api/scan/cau`（`views.py:394`）的 `files[].url` 只校验「是含非空 url 字符串的对象」，
  不校验 scheme，数据落 `ScanFiles.files` 后由 `ShowScFile.vue:29-36` 以 `:href="f.url"` 渲染
  在**管理员/组委会**的审核页上。左键被 `@click.prevent` 接管，中键/右键的
  「在新标签页打开」在 Chrome 下对 `javascript:` 亦被拦截 —— 故**危害受限，标为疑似**，
  需在目标浏览器实测；
- STS 直传（`views.py:1491-1500`）的 `ext` 取自客户端 `filename`，只校验 `[1:].isalnum()` 与长度，
  **与 `biz` 允许的 MIME 无关**，`contentType` 同为客户端声明值。`biz="image"` 配 `filename="a.html"`
  可通过，key 变成 `image/20260929/<uuid>.html`。是否构成存储型 XSS 取决于 OSS/CDN 是否按
  Content-Type 内联渲染、以及自定义域名是否与主站同源 —— **需运行时验证，本条标为疑似**。
  对照：后端代理路径 `/api/oss/upload` **有**扩展名白名单（`OSS_EXT_RULES`），只有 STS 路径缺这一环。

### M-08　审计类接口全字段下发

`GET /api/admin/person/list`（`views.py:795`）用 `list_page(qs, request, model_dict)`，
`model_dict` 返回模型全部字段，`Person` 含 `card`、`phone`；
